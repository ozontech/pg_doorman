# Режимы пула

pg_doorman поддерживает два режима пула: `transaction` и `session`. Режим задаётся для пула, при необходимости переопределяется для конкретного пользователя.

Режима `statement` нет.

## Транзакционный режим (рекомендуется)

```yaml
pools:
  mydb:
    pool_mode: "transaction"
```

Поддерживаются:

- Именованные и анонимные подготовленные запросы.
- Pipeline и асинхронный `Flush`.
- Отмена запросов через TLS.

## Сессионный режим

```yaml
pools:
  legacy_app:
    pool_mode: "session"
```

Используйте для клиентов, которым нужны:

- Параметры сессии (`SET search_path`, `SET TIME ZONE`).
- Подписки `LISTEN`.
- Курсоры `WITH HOLD` и advisory-блокировки между транзакциями.

## Переопределение для конкретного пользователя

Режим пула можно переопределить для конкретного пользователя:

```yaml
pools:
  mydb:
    pool_mode: "transaction"
    users:
      - username: "app"
        password: "md5..."
        pool_size: 40
      - username: "admin_tools"
        password: "md5..."
        pool_size: 4
        pool_mode: "session"
```

Полезно, когда одному пользователю (инструменты эксплуатации, миграции) нужна семантика сессии, а основное приложение остаётся в транзакционном режиме.

## Очистка при возврате в пул

По умолчанию включён `cleanup_server_connections: adaptive` без `cleanup_server_query`: pg_doorman очищает сессию только когда видит её изменение, поэтому кешированные prepared statements пулера переживают возврат соединения в пул.

Встроенная очистка отслеживает пять видов состояния сессии и отвечает очисткой:

- `SET` → `RESET ALL`.
- Курсор `DECLARE` → `CLOSE ALL`.
- SQL `PREPARE` → `DEALLOCATE ALL`. SQL `PREPARE` и extended-протокольный `Parse` делят одно пространство имён statements на сервере.
- `LISTEN` → `UNLISTEN *`.
- `CREATE TEMP TABLE` → `DISCARD TEMP`.

Каждая пачка очистки также снимает advisory-блокировки через `pg_advisory_unlock_all()`.

Не отслеживаются `SELECT ... INTO TEMP` и `CREATE TEMP TABLE AS SELECT`: они отвечают тегом внутреннего запроса. Временные объекты внутри функций тега не имеют. Для них используйте `always` с подходящим SQL.

В транзакционном режиме соединение возвращается в пул после каждого запроса. Временная таблица живёт одну транзакцию: держите транзакцию открытой для всех операторов, которые её используют.

`cleanup_server_query` заменяет встроенную очистку и требует `always`: собственный SQL выполняется при каждом возврате использованного соединения. С `adaptive` он несовместим, и такая конфигурация отклоняется при проверке. Режим дороже для сервера: запрос уходит на каждый возврат. С `DISCARD ALL` prepared statements ещё и пере-парсиваются после каждого возврата. `off` отключает очистку сессии. Незакрытые транзакции откатываются независимо от режима.

Полный список отслеживаемых операторов, ограничения и примеры для PostgreSQL и Greengage см. в [справочнике](../reference/pool.md#cleanup_server_connections).
